## Detailed Test Cases

### QA-001: Field Correction Mid-Flow
- **Setup**: `session_id: "qa001_session"`, `mode: reporting`. `location: "Bay 2"`, `equipment: "Valve 2"`.
- **Worker Action**: *"No, it was valve 4 not valve 2"*
- **Validation**:
  1. `state.report.equipment.value` equals `"Valve 4"`.
  2. `state.report.equipment.source` equals `"said"`.
  3. `create_near_miss` is NOT executed.
  4. Audit history records `field_corrected` event containing `{ field: "equipment", old_value: "Valve 2", new_value: "Valve 4" }`.

### QA-002: Interruption Mid-Procedure-Step Playback
- **Setup**: `session_id: "qa002_session"`, `mode: field_ops`, `current_step: 2`. Step 2 audio is playing.
- **Worker Action**: Barge-in spoken utterance: *"My gauge reads 15 PSI, is that safe?"*
- **Validation**:
  1. Audio playback is stopped (`status: interrupted`).
  2. `check_safety_threshold` dispatched with parameter `"pressure"`, value `15`, unit `"PSI"`.
  3. Spoken safety interrupt message generated first.
  4. `current_step` remains `2`.
  5. Agent resumes Step 2 text without advancing to Step 3.
  6. `get_next_step` is NOT called.

### QA-003: Safety Sentinel on Out-of-Range Spoken Value
- **Setup**: Coolant line pressure safe range: `min: 4.0`, `max: 10.0 PSI`.
- **Worker Action**: Utterance containing: *"Pressure is 15 PSI"*
- **Validation**:
  1. `check_safety_threshold` returns:
     ```json
     {
       "in_range": false,
       "measured_value": 15.0,
       "unit": "PSI",
       "expected_range": { "min": 4.0, "max": 10.0 },
       "deviation_pct": 83.3,
       "severity": "critical",
       "message": "WARNING: pressure is 15.0 PSI, which exceeds maximum safe threshold of 10.0 PSI by 83.3%!"
     }
     ```
  2. Agent speaks warning payload immediately.
  3. `check_safety_status.safe_to_report` gates report submission while worker remains exposed.
  4. Banner payload structured for FE-002 banner alert UI.

### QA-004: Session Resume after Disconnect (30s Window)
- **Setup**: Active session `qa004_session` drops WebSocket connection mid-report.
- **Worker Action**: Reconnect within 20 seconds using `session_id: "qa004_session"`.
- **Validation**:
  1. State restored (`mode`, `schema_state`, `pending_confirmation`).
  2. `idempotency_key` remains identical: `hash(worker_id + site + equipment + normalized_narrative + local_day)`.
  3. Call `create_near_miss` twice with same idempotency key -> returns `duplicate: true`, `created: true`, same `report_id`.
  4. Audit trail appends to `qa004_session`.
  5. Reconnect after 35s (> 30s window) creates new session without replaying old write.
